# Session continuity and documentation

Use [AGENTS.md](../../../AGENTS.md), [status](../../../docs/STATUS.md), [tasks](../../../tasks.md) and the task-relevant owner. Read actual source and exact-commit evidence before reconciling a prior summary. Archives are dated evidence, not current instructions.

For synchronization or a branch handoff, compare the actual checkout, remotes, local-only commits and both branch histories before selecting a next UI task. Use the existing [synchronization procedure](../../../docs/agents/codex.md#synchronize-the-existing-checkout) and the user's latest branch authorization; do not repeat a retired branch rule from a dated report. Preserve both implementations and report unresolved divergence. Do not create another checkout or assume a configured client integration is connected.

For documentation consolidation, inspect inbound links and unique requirements, update the single current owner, and retire duplicated active prose under [the documentation map](../../../docs/README.md). Prefer linking existing immutable evidence over copying old failures into the current resume note. This workflow does not require another repository-wide audit during ordinary UI work.

Preserve task/feature/source IDs and distinguish implemented, reproduced, tested, compared and accepted. Keep one product queue and the existing parity ledgers. Update the current resume note rather than append competing summaries or ask the owner to reconstruct prior context.

A handoff identifies the exact commit, changed behavior, actual checks, evidence paths, failure/not-run boundaries and next concrete action. Do not mark a service or source gate complete because docs were rewritten. Run the lightweight docs/skill checks for documentation-only changes and preserve immutable upstream files/licenses.
